# Аккаунты и рейтинг Playne

Вход только через Яндекс ID. Игры доступны гостям. Публикация в рейтинг требует входа и подтверждения ника. Старые localStorage-рекорды не импортируются.

## Интерфейс

`/account/` — вход, ник, лучшие опубликованные результаты, история последних 30 партий, выход и удаление профиля. При первом входе ник составляется из фамилии и имени Яндекса. Дальнейшие входы не перезаписывают ник. Ники могут совпадать: результаты привязаны к идентификатору аккаунта.

`/leaderboard/` — четыре игры, неделя и всё время. Один лучший результат игрока в игре. Неделя начинается в понедельник по Москве и определяется датой завершения партии, а не датой публикации. Равные очки дают одинаковое место; порядок равных строк стабилен по дате достижения. По 25 строк на странице, собственное место показывается отдельно при необходимости.

После гостевой партии кнопка сохранения открывает Яндекс и возвращает в кабинет с идентификатором партии. Результат восстанавливается с сервера, публикация выполняется после подтверждения ника. Гостевая cookie связывает результат с браузером. Повторная публикация идемпотентна. Для уже подтверждённого аккаунта сохранение выполняется прямо из игры.

## Сервер

Node.js 22+, Fastify, PostgreSQL. Сервис `playne-api.service` работает от отдельного пользователя `playne-api`, слушает только `127.0.0.1:3035`. Nginx проксирует `/api/`. База `playne`, роль `playne_app`; отдельная база `playne_test` используется только тестами. Другие проекты, их базы и доступы не меняются.

Схема: `server/schema.sql`. Пользователи, внешние идентификаторы, сессии входа, одноразовые OAuth-состояния, партии и ответы. Cookie сессии — случайный токен, HttpOnly, Secure, SameSite=Lax; в БД хранится SHA-256 токена. Срок входа 30 дней, OAuth-состояния 10 минут, неопубликованной партии 24 часа; очистка каждый час. После публикации географическая партия не хранит panorama ID или координаты, полученные из Google: остаются выбранные районы поиска, дистанции и оценки.

Яндекс: authorization-code flow, PKCE S256 и одноразовый state, привязанный к гостевой cookie. Идентификатор пользователя берётся из проверенного ответа Яндекса, а не из браузера. OAuth-токены используются для чтения профиля и не сохраняются. Пол и другие неиспользуемые поля профиля не сохраняются. Email не является идентификатором аккаунта или публичным ником. Разрешение — `login:info`.

Мутации требуют точный Origin сайта. Все SQL-параметры передаются отдельно. Доступ к чужой партии запрещён, ответы фиксируются по порядку и не могут изменяться после принятия. Дубли возвращают первоначальный ответ. На запросы действуют ограничения частоты и размера. В API access log не включены query string, cookies и тела запросов, чтобы код OAuth не попадал в журналы.

## Проверка очков

Сервер создаёт задания, затем принимает только ответы. Размеры, цвета, географические расстояния и траектория круга проверяются общими чистыми функциями. Клиентские `score`, `actual` и подменённые задания не являются источником оценки. Для круга координаты сначала округляются одинаково на клиенте и сервере.

В «Где я?» браузер ищет наружную официальную панораму, сервер независимо запрашивает её координату через Street View Static API metadata и проверяет близость к выбранному району. Эта координата используется и в интерфейсе, и для серверной оценки. Подмена панорамы после принятого ответа невозможна. При недоступной панораме альтернативу для рейтинговой партии выбирает сервер. Google-запросы идут по IPv4 с разрешённого IP VPS.

Проверка защищает от прямой подмены очков. Она не доказывает человеческое прохождение: бот может подобрать цвет, построить математический круг или воспользоваться координатами SDK. Рейтинг не предназначен для денежных соревнований.

При недоступном API начало партии переключается на локальную игру; такой результат в рейтинг не публикуется. Ошибка отправки существующей онлайн-партии позволяет повторить проверку без изменения уже принятых ответов.

## Настройки

Локальные секреты: `.env.auth.local`; файл исключён из Git. Продакшен: `/etc/playne/api.env`, владелец root, права 600. Сервер получает секреты через systemd EnvironmentFile. Они не имеют префикса VITE_ и не включаются в сборку браузера.

- DATABASE_URL
- YANDEX_CLIENT_ID
- YANDEX_CLIENT_SECRET
- YANDEX_REDIRECT_URI=https://playne.ru/api/auth/yandex/callback
- GOOGLE_STREET_VIEW_SERVER_KEY — только Street View Static API, IP VPS
- PLAYNE_ORIGIN=https://playne.ru
- PORT=3035
- PLAYNE_SCHEMA=/srv/playne/api/current/schema.sql

`npm run build:api` создаёт автономный Node-бандл и SQL-схему. CI упаковывает их вне публичной директории в `api/`. Деплой переключает сайт и API, перезапускает сервис и проверяет SHA API и статических страниц. Неуспешная активация восстанавливает обе ссылки. Миграции первой версии только создают недостающие таблицы и индексы.

Ежедневные резервные копии: `playne-db-backup.timer`, закрытая папка `/srv/playne/backups/database`, хранение 14 дней. Снимки содержат персональные и служебные данные и не доступны через Nginx. Перед восстановлением остановить API, восстановить копию в отдельную базу через pg_restore, проверить её и только затем переключать DATABASE_URL.

## Проверки

`npm test` — геометрия и общие проверки; интеграционные тесты включаются при TEST_DATABASE_URL, указывающем строго на `playne_test`. В CI поднимается отдельный PostgreSQL 16. Тесты проверяют OAuth-состояние и повтор callback, cookie и хеши сессий, завершение/порядок партий, публикацию и дубли, ник и выборки рейтингов. Провайдер в этих тестах заменён тестовой зависимостью; в production нет тестового входа или обходного маршрута.

Реальный OAuth проверяется отдельно через Яндекс с участием владельца аккаунта. Браузерные проверки включают сохранение гостевой партии после входа, ник, перезагрузку, повторный вход, все игры, рейтинги и мобильный экран. Кабинет имеет noindex и не включён в sitemap. Рейтинг, политика и правила включены в sitemap.
