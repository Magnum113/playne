# Аккаунты и рейтинг Playne

Вход только через Яндекс ID. Игры доступны гостям. После входа завершённые онлайн-партии автоматически сохраняются в рейтинг под текущим ником. Старые localStorage-рекорды не импортируются.

## Интерфейс

`/account/` — вход, ник, лучшие опубликованные результаты, история последних 30 партий, выход и удаление профиля. При первом входе ник составляется из фамилии и имени Яндекса. Дальнейшие входы не перезаписывают ник. Ники могут совпадать: результаты привязаны к идентификатору аккаунта.

`/leaderboard/` — десять игр, неделя и всё время; для четырёх игр раздела «Для ума» публикуются только задачи дня. Один лучший результат игрока в игре. Неделя начинается в понедельник по Москве и определяется датой завершения партии, а не датой публикации. Равные очки дают одинаковое место; порядок равных строк стабилен по дате достижения. По 25 строк на странице, собственное место показывается отдельно при необходимости.

После гостевой партии кнопка «Войти и сохранить» открывает Яндекс и возвращает в кабинет с идентификатором партии. Результат восстанавливается с сервера и автоматически публикуется. Гостевая cookie связывает результат с браузером. Для авторизованного игрока публикация запускается сразу после проверки последнего ответа, без отдельной кнопки и открытия итогового экрана. При ошибке доступно повторное сохранение. Повторная публикация идемпотентна; смена партии не переносит статус сохранения на другую партию. Подтверждение ника не требуется; изменить его можно в кабинете. Локальные партии без серверной проверки автоматически не публикуются.

## Сервер

Node.js 22+, Fastify, PostgreSQL. Сервис `playne-api.service` работает от отдельного пользователя `playne-api`, слушает только `127.0.0.1:3035`. Nginx проксирует `/api/`. База `playne`, роль `playne_app`; отдельная база `playne_test` используется только тестами. Другие проекты, их базы и доступы не меняются.

Схема: `server/schema.sql`. Пользователи, внешние идентификаторы, сессии входа, одноразовые OAuth-состояния, партии и ответы. Cookie сессии — случайный токен, HttpOnly, Secure, SameSite=Lax; в БД хранится SHA-256 токена. Срок входа 30 дней, OAuth-состояния 10 минут, неопубликованной партии 24 часа; очистка каждый час. После публикации географическая партия не хранит panorama ID или координаты, полученные из Google: остаются выбранные районы поиска, дистанции и оценки.

Яндекс: authorization-code flow, PKCE S256 и одноразовый state, привязанный к гостевой cookie. Идентификатор пользователя берётся из проверенного ответа Яндекса, а не из браузера. OAuth-токены используются для чтения профиля и не сохраняются. Пол и другие неиспользуемые поля профиля не сохраняются. Email не является идентификатором аккаунта или публичным ником. Разрешение — `login:info`.

Мутации требуют точный Origin сайта. Все SQL-параметры передаются отдельно. Доступ к чужой партии запрещён, ответы фиксируются по порядку и не могут изменяться после принятия. Дубли возвращают первоначальный ответ. На запросы действуют ограничения частоты и размера. В API access log не включены query string, cookies и тела запросов, чтобы код OAuth не попадал в журналы.

## Проверка очков

Сервер создаёт задания, затем принимает только ответы. Размеры, цвета, географические расстояния и траектория круга проверяются общими чистыми функциями. Клиентские `score`, `actual` и подменённые задания не являются источником оценки. Для круга координаты сначала округляются одинаково на клиенте и сервере.

В «Где я?» браузер ищет наружную официальную панораму, сервер независимо запрашивает её координату через Street View Static API metadata и проверяет близость к выбранному району. Эта координата используется и в интерфейсе, и для серверной оценки. Подмена панорамы после принятого ответа невозможна. При недоступной панораме альтернативу для рейтинговой партии выбирает сервер. Google-запросы идут по IPv4 с разрешённого IP VPS.

Проверка защищает от прямой подмены очков. Она не доказывает человеческое прохождение: бот может подобрать цвет, построить математический круг или воспользоваться координатами SDK. Рейтинг не предназначен для денежных соревнований.

При недоступном API начало партии переключается на локальную игру; такой результат в рейтинг не публикуется. Ошибка отправки существующей онлайн-партии позволяет повторить проверку без изменения уже принятых ответов.

## «Одной линией»

Идентификатор игры — `line`, страница — `/one-line/`. В каждой партии пять полей размером 4×4, 5×5, 5×5, 6×6 и 6×6. В режиме `classic` («Задача дня») сервер выбирает одинаковый набор по календарной дате Europe/Moscow; в `practice` создаёт случайную пятёрку. Рейтинги режимов разделены. В общем зачёте учитывается только лучший завершённый опубликованный результат задачи дня; вклад `line` — результат из 500 × 2. Предыдущие пять вкладов сохраняют прежние формулы.

Первый запрос задачи дня резервирует попытку в `playne_line_days`: уникальные ограничения действуют для браузера/даты и аккаунта/даты. Повторный запрос возвращает существующую партию, в том числе завершённую; время и подсказки не сбрасываются. Новому браузеру того же аккаунта соответствует та же попытка. Одна гостевая партия на игру сохраняется для обоих режимов: незавершённая восстанавливается, после завершения нужен вход. При входе гостевой результат сохраняется. Если у аккаунта уже была другая попытка этого дня, гостевая партия публикуется в практике, не создавая второй результат дня.

Перед каждым полем клиент вызывает `POST /api/games/:id/line/start` с `index`. Сервер фиксирует `startedAt` один раз и возвращает `serverNow`, `startedAt` и число подсказок. `POST /api/games/:id/line/hint` принимает `index`, текущий `path` и UUID `requestId`: под блокировкой строки сохраняет подсказку и её стоимость, исправляет ошибочный префикс пути и добавляет следующий канонический шаг. Повтор того же `requestId` не списывает вторую подсказку. В публичной партии доступны счётчик и время начала; внутренний журнал запросов и готовое решение не возвращаются.

Обычный `/answers` принимает только полный путь. Сервер проверяет соседство, стены, уникальность клеток и последовательность чисел. Очки поля: 80 за завершение плюс до 20 за время минус 15 за каждую серверную подсказку, с нижней границей 0. Полный бонус сохраняется до ориентира `parSeconds`, затем линейно убывает до нуля при четырёхкратном времени. Медленное решение без подсказок получает 80. Время рассчитывается от серверного старта до принятия ответа, в том числе при закрытой вкладке. Клиентские очки, время и число подсказок игнорируются. Undo и перезапуск пути бесплатны и не перезапускают часы.

Схема безопасно расширяет существующие allowlist-ограничения `playne_games` и `playne_guest_trials`. Интеграционные проверки `server-tests/line.test.ts` покрывают одинаковые задачи дня, конкурентный старт, повтор завершённой попытки, гостевой лимит, восстановление времени, идемпотентные подсказки, неверные пути, подмену клиентских полей, практику вне общего зачёта и конфликт гостевого сохранения с попыткой аккаунта.

## Настройки

Локальные секреты: `.env.auth.local`; файл исключён из Git. Продакшен: `/etc/playne/api.env`, владелец root, права 600. Сервер получает секреты через systemd EnvironmentFile. Они не имеют префикса VITE\_ и не включаются в сборку браузера.

- DATABASE_URL
- YANDEX_CLIENT_ID
- YANDEX_CLIENT_SECRET
- YANDEX_REDIRECT_URI=https://playne.ru/api/auth/yandex/callback
- GOOGLE_STREET_VIEW_SERVER_KEY — только Street View Static API, IP VPS
- PLAYNE_ORIGIN=https://playne.ru
- PORT=3035
- PLAYNE_SCHEMA=/srv/playne/api/current/schema.sql

`npm run build:api` создаёт автономный Node-бандл и SQL-схему. CI упаковывает их вне публичной директории в `api/`. Деплой переключает сайт и API, перезапускает сервис и проверяет SHA API и статических страниц. Неуспешная активация восстанавливает обе ссылки. Миграции первой версии только создают недостающие таблицы и индексы.

Ежедневные резервные копии: `playne-db-backup.timer`, закрытая папка `/srv/playne/backups/database`, хранение 14 дней. Снимки содержат персональные и служебные данные и не доступны через Nginx. Перед восстановлением остановить API, восстановить копию в отдельную базу через pg_restore, проверить её и только затем переключать DATABASE_URL.

## Проверки

`npm test` — геометрия и общие проверки; интеграционные тесты включаются при TEST_DATABASE_URL, указывающем строго на `playne_test`. В CI поднимается отдельный PostgreSQL 16. Тесты проверяют OAuth-состояние и повтор callback, cookie и хеши сессий, завершение/порядок партий, публикацию и дубли, ник и выборки рейтингов. Провайдер в этих тестах заменён тестовой зависимостью; в production нет тестового входа или обходного маршрута.

Реальный OAuth проверяется отдельно через Яндекс с участием владельца аккаунта. Браузерные проверки включают сохранение гостевой партии после входа, ник, перезагрузку, повторный вход, все игры, рейтинги и мобильный экран. Кабинет имеет noindex и не включён в sitemap. Рейтинг, политика и правила включены в sitemap.

## Правила «Где я?» версии 4

Пять раундов по 100 очков, максимум 500. Только целые очки: до 250 м — 100; дальше `min(99, round(100 * exp(-distanceKm/2000)))`. За 1000 км — 61, за 2000 км — 37. Итог — сумма пяти целых оценок. При одинаковом итоге место в рейтинге одинаковое. Общая БД продолжает хранить score_units в десятых для остальных игр; для новых географических партий значение кратно 10.

Четыре режима имеют отдельные рекорды и рейтинги: `classic` — без перемещения и без таймера; `timed` — без перемещения, три минуты на раунд; `moving` — с перемещением, без таймера; `moving-timed` — с перемещением, три минуты на раунд. Режим хранится в существующем столбце mode и задаётся сервером при создании партии, клиент не может поменять его через ответы. Стартовая панорама и координата проверяются один раз; сервер не разрешает подменять их при прогулке. Навигация остаётся внутри одного объекта Google StreetViewPanorama. Старые режимы и их результаты сохраняются; новый режим доступен клиентам версии 4. После загрузки панорамы `/ready` один раз записывает серверный deadline; повторный запрос не продлевает время. `/pin` фиксирует выбранную точку только до срока. После срока `/answers` использует последнюю серверную точку либо 0 очков без неё, игнорируя позднюю клиентскую точку. Клиент отсчитывает до абсолютного срока и обрабатывает возврат из фоновой вкладки. Время загрузки и экран результата не расходуют лимит раунда.

Новый клиент создаёт `geoRulesVersion=4` и передаёт `X-Playne-Geo-Version: 4`. В актуальный рейтинг, историю и лучшие результаты входят и version=2/3: каждый прежний раунд приводится к шкале 100 (v2 делением на 50, v3 без деления), округляется до целого и ограничивается 99 для неточного попадания. Итог складывается из конвертированных раундов; одинаковые итоги получают одинаковый ранг. Исторические записи в БД не переписываются. Старые клиенты version=2/3 продолжают завершать партии и получать свою исходную шкалу и точность. Самые ранние version=1 остаются отдельно в истории как «Прежние правила».

Браузерные рекорды хранятся в `playne:geo:v4:<mode>` для всех четырёх режимов. Если новой записи нет, читается v3, затем v2: итог округляется до целого после приведения к шкале 500. Число партий и недавние локации сохраняются; старые ключи не удаляются. Поскольку в localStorage хранится только общий рекорд, его округление может отличаться от суммы отдельно округлённых раундов серверной партии.

Источники исследования формата: [официальные правила Daily Challenge, 5 мест и 3 минуты](https://www.geoguessr.support/support/solutions/articles/206000056710-what-is-the-daily-challenge-), [официальное описание действий GeoGuessr](https://www.geoguessr.support/support/solutions/articles/206000056750-what-is-geoguessr-). Шкала 100/500 — решение Playne; точная внутренняя формула GeoGuessr не заявляется скопированной.

## Надёжное сохранение результата

С 14 октября 2026 года последний проверенный ответ авторизованного игрока завершает и публикует партию одной транзакцией на сервере. Публикация идемпотентна; повтор ответа не меняет очки и дату достижения. Гости остаются вне рейтинга до входа. Координаты ответов и данные проверки панорам «Где я?» удаляются из опубликованного задания, как и при ручной публикации.

`src/rankedQueue.ts` хранит ещё не подтверждённые ответы в `playne:ranked-pending:v1`, повторяет отправку с задержкой 2–30 секунд, после возврата соединения и при открытии сайта. Очередь переживает перезагрузку, переход к другой игре и начало следующей партии; записи разных вкладок объединяются. Результаты принимает и считает сервер; браузер не отправляет готовый счёт. При недоступном localStorage отправка продолжает работать в памяти. Серверное задание для неопубликованной партии доступно 24 часа.

«Оттенок» сохраняет `rankedId` вместе с цветами и ответами. Для прежнего формата без ID `/api/games/resume` ищет уже выданное задание по точному набору пяти цветов и текущей гостевой cookie или аккаунту. Новое задание для старого счёта не создаётся. Если серверного задания никогда не было или оно уже удалено, нельзя безопасно включить локальный рекорд в рейтинг.

«На глаз», «Оттенок» и «Где я?» начинают новую партию после получения задания с сервера; сетевой сбой больше не подменяет его несохраняемой локальной игрой. «Круг» хранит саму линию до отправки и может создать серверную попытку после восстановления соединения. В географической игре сбой регистрации панорамы или таймера оставляет раунд для повтора, не теряя связь с партией.


## Четыре игры «Для ума»

Идентификаторы `flash`, `rotate`, `slide`, `dispatch`, страницы `/brain/{game}/`. Каждая партия состоит из пяти раундов, максимум — 500, версия очков — 1. `classic` — одинаковая для всех задача дня на базовой сложности 1 по дате Europe/Moscow, замороженной при создании партии; `practice` — случайный набор на сложности 1–3. В практике «Передвинь» исключены все пять сегодняшних дневных полей на любой сложности.

`playne_brain_packs` хранит закрытый неизменный набор на игру/дату/версию 1. Первый запрос создаёт его из криптографически случайного seed и сохраняет всю структуру; seed не хранится и не возвращается. Конкурентные запросы используют INSERT ON CONFLICT и читают уже сохранённый набор. Генератор в браузере и известная дата не позволяют восстановить дневной образец. Каждая партия получает отдельную глубокую копию, поэтому время и подсказки одного игрока не меняют задания остальных. Практика «Передвинь» исключает реальные идентификаторы сохранённого дневного набора.

`playne_brain_days` резервирует первую попытку отдельно для игры/даты/браузера и игры/даты/аккаунта. Повторный запуск возвращает ту же партию и принятые ответы. При входе гостевой результат привязывается к аккаунту; если у аккаунта уже есть другая попытка за ту же дату и игру, гостевая партия становится приватной практикой. Первая гостевая партия на каждую игру сохраняется для выбранного режима: незавершённую можно продолжить, после завершения нужен вход. Блокировка публикаций, затем блокировки даты/аккаунта и строки партии используют согласованный порядок.

Перед каждым раундом клиент вызывает `POST /api/games/:id/brain/start` с `index`. Сервер один раз сохраняет `startedAt`, возвращает безопасный `round`, `serverNow`, `hints` и для «Вспышки» `revealUntil`. Правильные клетки доступны через start только внутри первоначального окна показа; GET партии никогда не возвращает их в challenge. Повторный start и перезагрузка не начинают показ заново. Ответ до окончания показа отклоняется. Правильный признак отражения «Поворота» также скрыт из публичного задания. После принятия ответа сервер возвращает исправление внутри соответствующего `answers[index]` для разбора.

`POST /api/games/:id/brain/hint` принимает для «Передвинь» `index`, текущие `moves` и UUID `requestId`. Под блокировкой строки сервер валидирует историю ходов и сохраняет подсказку и её счётчик. Повтор одного requestId возвращает ту же подсказку без нового списания; каждая новая подсказка снимает 15 очков, даже после отмены и сброса на клиенте. Полный ответ должен воспроизводить допустимое решение. «Диспетчер» воспроизводит хронологический журнал переключений: нельзя менять неактивные стрелки, указывать события за пределами волны или закончить раньше её серверной длительности. Во всех четырёх играх клиентские score, hints и elapsedMs не определяют оценку. Время сохраняется для личной статистики и не даёт очков.

Практика хранится в истории владельца, включая гостевую практику после входа, и никогда не публикуется. Все публичные SQL-запросы отдельно отсекают такую практику даже при ошибочно заполненном published_at; запрос её рейтинга возвращает 400. Завершённая практика владельца не удаляется общей очисткой неопубликованных партий через 24 часа. Удаление аккаунта удаляет и приватные результаты.

`GET /api/brain/progress` возвращает собственные `today.results`, скользящие `last7Days`, `weeklyDays` и `goal: {days:3,completedDays}`, `suggestedLevels` и последние 30 завершённых партий `history`. Календарь интерфейса строится по серверной дате `today.day`: понедельник–воскресенье текущей недели, выполненные дни заполняются из `last7Days`, будущие остаются пустыми. Неделя начинается в понедельник по Москве; день активности — московская дата завершения хотя бы одной полной партии любой игры Playne в любом режиме, включая практику. `last7Days`, `weeklyDays`, `goal` и `milestones` относятся к общей личной активности; `today.results`, `history` и `suggestedLevels` остаются статистикой четырёх Brain-игр. Для гостя общая активность ограничена его собственными текущими пробными партиями; для вошедшего — только партии владельца. Рекомендация сложности использует последние три практики на последней выбранной сложности: среднее от 400 повышает её, до 200 понижает; границы 1–3. Прогресс не содержит шаблонов, правильных ответов или журналов переключений. Сводки считаются в БД; история и выборка для рекомендации ограничены отдельно, чтобы новые партии не скрывали старые результаты другого уровня.

Общий зачёт версии 3 содержит семь категорий и максимум 7000: прежние шесть вкладов сохранены, категория `brain` добавляет `floor(сумма четырёх лучших опубликованных дневных результатов / 2)`, до 1000. `GET /api/leaderboard?game=brain` показывает отдельный агрегат четырёх игр, где каждый вклад равен результату / 2, до 250; половины балла сохраняются в отдельных вкладах, итог округляется вниз. Практика не влияет на этот агрегат. Старые записи и формулы остальных игр сохраняются.

`server-tests/brain.test.ts`, `brain-queue.test.ts`, `overall.test.ts` проверяют полное прохождение четырёх игр, конкурентные дневные старты, коллизию гостевого входа, окна показа и перезагрузку, серверные таймеры, подсказки, допустимость ходов и переключений, приватность практики, границы агрегации и миграцию старых ограничений. Интеграционные тесты запускаются только с TEST_DATABASE_URL, указывающим на отдельную базу playne_test.


## Возвращение и общая активность

`GET /api/play/progress` (`Cache-Control: no-store`) возвращает приватные `day`, `weekStart`, `last7Days`, полную неделю `week`, `weeklyDays`, `goal`, постоянные `milestones`, частоты законченных игр за 30 дней `favorites`, статусы сегодняшних Brain/Line задач `daily` и 32 недавних завершения `recentCompletions`. Доступ — только текущий владелец или собственные guest trial IDs. Ответы, seed и закрытый challenge не возвращаются.

Общая цель отделена от рейтинга: одна завершённая партия при любом результате даёт активную московскую дату; повторные партии не умножают дни. `completedWeeks` считает календарные недели с тремя активными датами, `tenDayMonths` — месяцы с десятью. История для этих счётчиков не ограничена 30 партиями.

На главной «Сегодня в Playne» предлагает незавершённую задачу дня, затем подходящую любимую игру, затем стабильный выбор на дату; рядом одна дополнительная игра. Завершённые daily не предлагаются как новые, полностью пройденный набор подтверждается отдельно. После Brain-результата общий прогресс запрашивается заново: отметка «сегодня засчитан» появляется только по подтверждённому ID завершения. Вход/повтор сохранения/новая дата сохраняют приоритет единственного основного действия.
