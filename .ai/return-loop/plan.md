# Playne: план возвращаемости

Дата: 30 октября 2026. Внутренний план; наличие пункта здесь не означает, что он реализован.

## Решение и границы первого релиза

Первый выпуск реализовал пункты 1–3. Текущий выпуск реализует пункты 4–6: личные игровые показатели, вызовы на те же задания с PNG/Open Graph и общую добровольную подписку. В основном потоке показываем результат, короткое подтверждение личного прогресса и один следующий шаг. Достижения, подробная история, друзья и настройки раскрываются по запросу. Цепочки модальных окон, обязательные серии ежедневных побед и автоматический запуск следующей партии не нужны.

Ответственность: root — Today, Weekly и общий hook; server agent — серверная агрегация; result agent — экран результата Brain. Этот документ не изменяет код.

### Общие инварианты

- Личная цель — **три разных активных дня календарной недели**, с понедельника по воскресенье по Москве. Любая полностью завершённая сервером партия любой из **10 игр**, включая практику и нулевой результат, засчитывает день. Повторы в тот же день не добавляют дней.
- Новый источник — **`/play/progress`**. Счётчики строятся по полной истории завершений, а не по последним 30 записям UI. На исходном срезе `/brain/progress` ограничивал недельную активность четырьмя brain-играми и `classic`; этот расчёт должен использовать общую цель.
- `completedWeeks` — число календарных недель с тремя и более активными датами, включая текущую неделю после достижения порога. Недели могут быть **не подряд**. Постоянные достижения: первая такая неделя и четыре такие недели.
- `tenDayMonths` — число календарных месяцев с десятью и более активными датами. Счётчик сохраняется после смены месяца.
- Недельный/месячный текущий прогресс начинается с нуля в новом периоде; уже полученные достижения и накопленные счётчики остаются. Повторный запрос, повтор публикации или перенос гостевой партии в аккаунт не выдаёт награду повторно.
- Неполная партия и неподтверждённый локальный ответ не засчитываются. При отложенной отправке показываем ожидание подтверждения; после синхронизации день восстанавливается по серверной дате завершения.
- **Рейтинг не меняется:** формулы, режимы, первая дневная попытка, публикация, нормализация и места остаются прежними. Личная цель не начисляет рейтинговых очков. Практика сохраняет существующие правила видимости.
- **`today 0/4` на Brain остаётся счётчиком четырёх общих задач дня.** Он не равен общей недельной цели. Остальные игры также засчитывают личный день, но это не превращает их случайные партии в общие дневные задания.

### Даты и идентичность

| Смысл | Источник даты |
| --- | --- |
| Общая задача дня и её рейтинг | Дата набора `challenge.day`, Москва |
| Активный день личной цели | Серверный `completed_at`, переведённый в Москву |
| Недельный прогресс и достижения | Календарная неделя активной даты, начало в понедельник |
| Месячный прогресс | Календарный месяц активной даты |

Партия вчерашнего набора, завершённая после полуночи, сохраняет свой дневной набор, но личный активный день относится к фактическому завершению. Такое правило требуется одинаково применять в API, Today, Brain, профиле и сообщениях результата.

Для гостя используем только его действующую серверную browser identity; для аккаунта — проверенный owner. После входа переносим только разрешённые гостевые партии и объединяем даты, а не складываем счётчики. При выходе, смене аккаунта или identity старый прогресс сразу скрывается; запоздалый ответ предыдущего запроса не может заполнить интерфейс нового пользователя. Избранное/история не должны попасть к другому аккаунту на общем устройстве.

Новая дата проверяется на focus, возвращении видимости и редком date-check. Исторический `?result=` читается как история: смена даты не запускает партию и не заменяет старый результат. После возвращения на страницу можно предложить сегодняшнюю задачу отдельным действием.

## 1. Результат Brain: личный день и один следующий шаг — сейчас

**Задача.** Завершить игровую историю понятным результатом и предложить одну уместную следующую задачу.

**Основной экран.** Сначала итог партии и её короткий разбор. Затем одна строка: «День засчитан · 2 из 3 на этой неделе» либо «Сегодня уже засчитано · 2 из 3». Основная кнопка ведёт к одной незавершённой общей задаче дня. Рейтинг, практика и подробная история остаются вторичными ссылками.

**Выбор продолжения.** Учитывать достоверный pending, избранное и факт завершения текущей даты. Начатая подходящая партия предлагается как «Продолжить …». Уже пройденная задача повторно не выдаётся как новая. Если подходящих задач нет: короткое завершение «На сегодня всё готово», вторичная практика и возможность вернуться завтра. Переход по ссылке не запускает таймер следующего раунда.

**Зависимости.** Подтверждённое завершение партии; общий `/play/progress`; актуальные статусы задач дня для текущего пользователя; единая функция выбора следующей игры; существующий доступ гостя/Яндекс; готовые result/resume routes.

**Состояния.** Сохранение → подтверждено впервые сегодня / уже засчитано; API недоступен → результат остаётся, подтверждение дня ожидается; доступная next / pending / все пройдены; гость с использованной пробой → существующий вход; исторический результат → дата результата явно сохранена, дневная рекомендация относится к сегодня. Нельзя показывать «день засчитан» до подтверждения API.

**Метрики.** Доля увидевших результат, начавших и завершивших рекомендованную игру; время до следующего действия; D1/D7; число активных дат недели. Отдельно считать клики и реальные старты, чтобы автопереходы/повторный render не имитировали рост. Guardrails: завершение исходной партии, ошибки сохранения, выход с результата, доля многократных бесполезных рекомендаций.

**Проверки.** Все четыре Brain; первый и повторный зачёт дня; практика; ноль очков; pending; all-done; гостевой login gate; задержка/сбой API и повтор отправки; новый день при открытой вкладке; чтение старого результата; один основной CTA; 320 px, клавиатура, reduced motion. Изменение прогресса и загрузка рекомендации не прокручивают страницу и не переносят фокус.

## 2. Today на главной: основная задача и необязательное продолжение — сейчас

**Задача.** Сократить выбор до понятного следующего действия, сохранив весь каталог доступным.

**Основной экран.** Карточка «Сегодня» с датой и одной основной кнопкой. Дополнительная игра показывается компактно как необязательный вариант; полный каталог остаётся ниже. Для зачёта личного дня достаточно одной полной партии.

**Правило рекомендации.** Сначала достоверная незавершённая партия, затем подходящая незавершённая задача из избранного, затем предсказуемый запасной порядок. Дополнительный вариант должен отличаться от основного. Избранное влияет на выбор, но не создаёт обязательство пройти все любимые игры. При отсутствии данных используем нейтральную рекомендацию без заявлений о персонализации.

**Зависимости.** Общий прогресс и дата; надёжные pending/current-day statuses; известный список игр и их routes; источник избранного с границами identity; общий selector с пунктом 1. Не делать вывод о завершённости по наличию локального рекорда или ограниченной истории.

**Состояния.** Новый посетитель; возвращающийся без избранного; несколько favorites; pending; основная готова, дополнительная ещё нет; всё завершено; гость заблокирован только правилами существующей пробы; loading / stale / offline. Недоступность прогресса не блокирует каталог и не стирает уже показанный результат.

**Метрики.** Доля визитов главной с началом полной партии; время от входа до старта; доля вернувшихся в следующий день; использование основной/дополнительной рекомендации; доля продолжений pending. Guardrails: случайные клики и быстрые возвраты, недоступные рекомендации, лишние проверки доступа, ухудшение обнаружения остальных игр.

**Проверки.** Стабильный выбор при одном наборе данных; отсутствие дубликатов; изменение favorites; завершение в другой вкладке; guest → account → logout; запоздалые ответы; полночь и понедельник; all-done; данные недоступны; 320 px и клавиатура. Загрузка Today не запускает игровой timer и не создаёт новую дневную попытку.

## 3. Единая личная цель и постоянные достижения — сейчас

**Задача.** Показать накопленный результат возвращений без требования не пропускать ни дня.

**Основной экран.** Компактный календарь ПН–ВС и «2 из 3 дней». После достижения цели: «На этой неделе получилось»; четвёртый–седьмой активные дни можно отметить без новой обязательной планки. Постоянные достижения видны рядом с профилем/подробностями, без блокирующего поздравления после каждой партии.

**Зависимости.** Полная серверная агрегация десяти игр и всех режимов; уникальные активные даты; календарные границы Москвы; идемпотентные `completedWeeks`/`tenDayMonths`; перенос guest → account; единый hook для Today, результата Brain, BrainHub и профиля. Остальные игры сразу дают зачёт, даже если их экраны результата пока не показывают новый блок.

**Состояния.** 0/1/2/3+ дня; первый зачёт недели; первая успешная неделя; четвёртая успешная неделя, включая непоследовательные; 9/10+ дней месяца; новый период при сохранённых наградах; история отсутствует; подтверждение ожидается; identity сменилась. Для прошлой активности выполнить полный расчёт или явно согласованное восстановление; последние 30 партий не подходят для постоянных счётчиков.

**Метрики.** Распределение активных дней недели; доля дошедших до 2 и 3 дней; число недель с выполненной целью на пользователя; месяцы с 10+ днями; D7/D28. Не принимать рост числа партий в один день за рост регулярности. Guardrails: возврат после пропуска, доля пользователей с 0/1 днём, ошибки или задвоения наград.

**Проверки.** Десять игр × доступные режимы; полная партия с нулём; неполная не считается; пять партий за день дают один день; воскресенье → понедельник; конец месяца/года; UTC/Moscow граница; поздняя синхронизация; два параллельных завершения; повтор публикации/claim; больше 30 партий; четыре непоследовательные успешные недели; сохранность наград при rollover; удаление аккаунта согласно действующему порядку удаления данных.

## 4. Видимый рост конкретного игрового навыка — текущий выпуск

**Задача.** Показывать сравнение с собственными сопоставимыми попытками, которое помогает выбрать следующую тренировку.

**Минимальный вариант.** Один факт после результата: точность памяти на том же размере поля; верные ответы на том же классе фигур; число ходов относительно оптимума; доля правильно доставленных поездов на сопоставимой волне. Подробный график — по ссылке. Это игровая статистика, без обещаний роста IQ или переноса навыка вне игры.

**Зависимости.** Версия правил, сложность и параметры задания; достаточная личная история; единые определения метрик. Повторные попытки одной задачи и daily/practice разделяются. Средние по аудитории и процентили вводятся только при достаточной и понятной выборке; на старте достаточно личного сравнения.

**Состояния.** Недостаточно попыток; первые сопоставимые результаты; улучшение; стабильность; ухудшение; смена версии/сложности; история старого формата. Малую выборку не превращать в уверенный вывод. Падение результата не сопровождается наказанием или автоматическим усложнением.

**Метрики.** Просмотр личного разбора → добровольный выбор подходящей практики → завершение; повторные активные дни на том же навыке. Guardrails: выходы после негативного сравнения, чрезмерно сложные рекомендации, несопоставимые сравнения.

**Проверки.** Нет истории; 1–2 попытки; разные уровни и версии; подсказки; смешение разных размеров/волн; крайние результаты; формула подписи совпадает с расчётом; объяснение доступно без модального обучения. Рейтинговая формула не меняется.

## 5. Соревнование с другом на одной дате — текущий выпуск

**Задача.** Дать понятный повод поделиться завершённой задачей и сравнить результаты в небольшом круге.

**Минимальный вариант.** Вторичное действие «Позвать друга» после результата. Карточка содержит игру, дату и результат, но не решение. Получатель видит ту же дату/режим/версию задания; до собственной попытки чужие детали решения скрыты. Для прошедшей даты заранее определить доступность архива; нельзя выдавать сегодняшнюю случайную задачу за ту же самую.

**Зависимости.** Стабильная идентичность дневной задачи; явное пользовательское действие Share; безопасная ссылка и ограниченная видимость результата; правила архива/expiry; защита от повторной рейтинговой попытки и перечисления чужих партий. Полная социальная сеть и глобальный рейтинг друзей не нужны для первой проверки идеи.

**Состояния.** Приглашение открыто до/после собственной игры; задача ещё доступна / истекла; гость / аккаунт; уже завершено; ссылка недействительна; владелец удалил результат. Личный недельный прогресс и история по такой ссылке не раскрываются.

**Метрики.** Явная отправка/копирование → открытие приглашения → старт той же задачи → завершение → возврат участников в другой день. Отдельно измерять новые и существующие аккаунты. Guardrails: утечка ответа, жалобы, спам, недоступная дата, вынужденная регистрация до понимания приглашения.

**Проверки.** Совпадение даты/версии/режима; просмотр чужой ссылки; expiry; отозванная ссылка; первая попытка уже была; мобильный share/copy fallback; отсутствие секретных ответов и закрытой истории в URL, OG и аналитике. Автоматически отправлять сообщения друзьям не требуется.

## 6. Явные добровольные напоминания — текущий выпуск

**Задача.** По просьбе пользователя напоминать о доступной новой задаче в удобное время.

**Минимальный вариант.** Вторичная ссылка после успешной партии или настройка в профиле. Канал и время выбираются явно. Настройка не заслоняет результат, не становится условием игры и не появляется при каждом заходе. Разрешение браузера запрашивается только после выбора соответствующего канала.

**Зависимости.** Существующая модель consent и настроек; отдельное согласие на этот тип напоминаний; подтверждённый email для email-канала; часовой пояс/тихие часы; unsubscribe; идемпотентная доставка; проверка, что задача ещё не завершена. Адрес из входа и разрешение на письма о топ-10 сами по себе не разрешают новые напоминания.

**Состояния.** Не предлагалось / отказ / добровольно включено / канал не подтверждён / разрешение браузера отклонено / временно недоступен / выключено. Мягкое прекращение неактуальных напоминаний и возможность вернуться без потери прогресса. Никаких автоматических подписок.

**Метрики.** Добровольное включение; доставлено → осмысленный переход → завершённая партия; активные дни; отписки и жалобы. Для оценки эффекта — согласованная контрольная группа среди согласившихся, а не сравнение мотивированных подписавшихся со всеми остальными.

**Проверки.** Consent по назначению; верификация адреса; смена адреса/identity; unsubscribe; повтор worker/job; уже сыграно; полночь и timezone; недоступный канал; тихие часы; отказ от браузерного permission без повторного давления. Отправки в рамках пунктов 1–3 нет.

## Очерёдность и приёмка первого релиза

1. Серверный общий учёт дней, периодов и постоянных достижений; тесты полной истории и identity.
2. Общий hook и selector следующего шага, с loading/error/stale и защитой от запоздалых ответов.
3. Согласованные Today / Weekly / результат Brain. Старый счётчик daily 0/4 сохраняет свой смысл.
4. Интеграционная проверка всех десяти источников завершения; реальные переходы результата → рекомендованная игра; мобильная и клавиатурная проверка; контроль отсутствия нового auto-scroll и auto-start.
5. Проверка сохранности гостевого входа, приватной практики, общего рейтинга и email consent. Затем обычный независимый review и действующий порядок выпуска.

Для причинного вывода о возврате желательно стабильное распределение вариантов на identity до первого показа функции, заранее выбранные D1/D7/активные даты и сегменты guest/account. Если релиз идёт без эксперимента, сравнение до/после является наблюдением с влиянием состава аудитории и дат, а не доказательством эффекта функции. Открытая вкладка, фоновый polling и автоматическое обновление даты не считаются возвращением.

У Puzzmo обязательны первые две игры для серии; здесь зачёт личного дня наступает после одной полной партии. Публичного измерения эффекта нового релиза нет.
- [Puzzmo: новый экран завершения, 18.04.2024](https://blog.puzzmo.com/posts/2024/04/18/completion-sidebar-2/) — собственная история и личные рекорды стали заметнее глобального соревнования. Это продуктовый аргумент за порядок информации в результате, а не опубликованный A/B-эффект.
- [NN/G: Progressive Disclosure, 03.12.2006](https://www.nngroup.com/articles/progressive-disclosure/) — основные действия доступны сразу, редкие и подробные настройки раскрываются по запросу. В Playne это один основной CTA, короткое подтверждение цели и вторичные ссылки, а не длинная обязательная последовательность экранов.

Источники проверены 30.10.2026. Численные обещания роста retention в план не заложены.


## Уточнения реализации второго выпуска

- Разбор четырёх Brain игр основан на сырых показателях; baseline требует минимум три сопоставимые прошлые партии. Неизвестные legacy-параметры не превращаются в сравнение. Повторы по вызову исключены из baseline и подбора сложности.
- Вызовы доступны для четырёх Brain игр и «Одной линией». Current daily использует исходную первую попытку; практика и архивные даты запускают точную приватную копию со свежими таймерами и подсказками. Сравнения не публикуются в рейтинге и не улучшают публичный рекорд.
- Приглашение создаётся явно, содержит только ник/игру/дату/счёт. SSR HTML и PNG1200×630 доступны чат-ботам без JS. Непредсказуемый токен, отзыв, удаление с аккаунтом; без ответов/seed/email. На максимальном счёте призыв «Сможешь повторить?».
- Подписка везде общая: новые игры, напоминания и результаты. Старое rank-only согласие не расширяется автоматически. Для general новых подписчиков начальное расписание Пн/Ср/Пт19:00МСК; пользователь может изменить дни/время. Общие лимиты rank+reminder — одно/24ч и три/7д; нет писем после завершённой сегодня партии; unsubscribe отключает всё. Реальные адреса не используются в тестах.
