# Аналитика писем Playne

Отчёт `/api/email/report` и блок статистики в кабинете доступны только
`PLAYNE_EMAIL_ADMIN_ID`. Обычные пользователи не получают агрегированные данные.

## Два разных периода наблюдения

- Текущая статистика: отправки за последние 90 дней, без задержки в семь дней.
  Типы `rank`, `reminder`, `verify` показаны отдельно. Итоговое число уникальных
  получателей считается напрямую, а не суммируется по типам.
- A/B/C: только `rank-email-design-v1`. Первичная таблица показывает все текущие
  отправки. Для сравнения дизайнов есть отдельное раскрытие: доставленные письма
  старше семи дней, действия только в течение семи дней после отправки.
  Если таких писем ещё нет, показываем дату первого полного окна вместо таблицы
  нулей. Небольшая выборка не определяет победителя.

Раньше кабинет показывал только вторую выборку: реальные свежие доставки поэтому
выглядели как отсутствие писем. Теперь текущий отчёт загружается при открытии
блока и сохраняет последние успешные данные при ошибке обновления.

## Значение показателей

- Принято: Unisender принял сообщение (`accepted`), это ещё не доставка.
- Доставлено: подписанное событие провайдера `delivered`, `opened` или `clicked`.
- Открыто: письма с событием `opened`/`clicked`; автоматические почтовые клиенты
  тоже могут создавать такие события. Это не доказательство чтения человеком.
- Нажали ссылку: письма с хотя бы одним событием провайдера или GET нашей ссылки;
  автоматические проверки также возможны.
- Вернулись: уникальные получатели, совершившие действие на сайте после перехода.
- Начали/завершили игру: уникальные владельцы, для которых сервер подтвердил
  соответствующее действие с атрибуцией к письму.

В статистику входят сообщения из `playne_email_outbox`. Ручные/тестовые отправки
из Unisender без этой связи не становятся участниками A/B/C-теста. Повторные
отправки одному человеку не увеличивают число уникальных получателей.

## Доставка событий

`/api/email/provider` проверяет подпись, проект, job, адрес и `outbox_id`.
Повторы дедуплицируются. `opened_at` и `provider_clicked_at` сохраняют первое
полученное событие. Открытия включены в события существующего вебхука проекта
Playne; другие проекты и настройки отправок не меняются.

Исторические открытия восстановлены из экспорта событий Unisender по совпадению
job и outbox_id. Произвольные ручные письма не импортировались. Повторных отправок
при восстановлении нет. Порядок согласий и лимиты частоты сохранены.
